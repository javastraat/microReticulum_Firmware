ScotMesh NomadNet Page Reference

Every page and API path a ScotMesh microReticulum node answers on its nomadnet destination, straight from ScotMesh.h — what each one shows, who can see it, and what it lets you do. Click a page to expand it.

Public Settings Access Device Telemetry LXMF alerts JSON API

Public

Reachable by anyone who can hear the node — no identity or password needed, unless noted.

I /page/index.mu — Home

The node's landing page — whatever the operator has chosen to make public.

  • Node name, battery gauge (10-block bar, %, voltage, charge arrow)
  • Uptime, path count (links to Routes), radio freq/SF, live airtime %, operator note
  • "Admin" link if you're already registered, or "Register" if password sign-up is on
  • Verified-identity line, firmware + board footer

Visitor view is configurable on the Settings → Home page.

r /page/r.mu — Routes

The node's path table: destination hash · hop count · last heard, 10 rows per page, short or full hash display.

b /page/b.mu — Neighbours

Peers this node has heard announce: destination hash · time since heard · name, paginated.

l /page/l.mu — Register

Request admin access with a password, if the operator has turned registration on. Goes straight to admin, or into an approval queue, depending on operator setting.

3 wrong tries locks you out for 15 min; 10 wrong tries mesh-wide pauses registration for an hour.

Settings

Reachable only once your identity is on the admin list — everyone else lands on an "Admins only" page instead.

s /page/s.mu — Settings hub

Menu into the six pages below, each with its current value shown inline.

n /page/n.mu — Name & announce
  • Node name (32 chars), operator note (22 chars)
  • Announce interval: 30m / 1h / 3h / 6h / 12h
  • Renaming re-announces the node immediately
h /page/h.mu — Home page
  • Checkboxes for what a visitor sees: battery, uptime, radio, paths, airtime, operator, routes-link
  • Telemetry API on/off switch
  • "Preview" link — see the visitor view live
g /page/g.mu — Map (rmap.world)
  • Paste a coordinate (lat, lon) + height in metres
  • Exact or ~1 km-rounded precision, publish on/off
  • Last-sent time once published, "Announce now" action
f /page/f.mu — Radio
  • Current frequency, bandwidth, SF, CR, TX power
  • Two one-tap presets: ScotMesh 868 / 433

5-minute reversible trial — auto-reverts unless you hit Keep.

w /page/w.mu — Role
  • Fixed relay · Access point · Mobile · End device
  • Relays forward traffic for others; end devices never do

Needs a restart to apply.

y /page/y.mu — Power
  • Battery-% threshold (5–60%), action below it: lower TX to 10 dBm, radio off until charged, or nothing
  • Separate hard cutoff: radio off below 3.3 V
  • Live flag if a limit is currently in effect

Access

c /page/c.mu — Access hub

Menu into Admins / Password / Change log, each with a live count.

k /page/k.mu — Admins
  • Up to 8 admin identity hashes, your own row marked "you"
  • Add by pasting a 32-hex identity hash

Removing an admin is confirm-gated; you can't remove the last admin.

p /page/p.mu — Password registration
  • On/off, and "needs approval" (routes new sign-ups into a queue instead of auto-admitting)
  • Set/change password (8+ chars) — salted + hashed, never stored in plain text
  • Outcome of the last registration attempt
j /page/j.mu — Change log

Last 32 admin actions: how long ago, what happened, which identity.

q /page/q.mu — Waiting for approval

Only reachable when "needs approval" is on. Shows pending registration requests and how long they've waited; approve or deny each.

Device

d /page/d.mu — Device hub

Menu into the five pages below.

e /page/e.mu — Health
  • Free RAM / flash, uptime, boot count, last reset reason
  • Radio noise floor, last RSSI/SNR, current + average airtime %
  • Packets rx/tx, path/announce/known-destination/link/neighbour table sizes
i /page/i.mu — Lights & Bluetooth
  • LED mode: on / off / first 10 min only — errors always show regardless
  • "Blink for 30s" locator action
  • Bluetooth on/off, "unpair all paired phones" (where supported)
o /page/o.mu — Logs

Last 5 log lines, with a refresh action.

x /page/x.mu — Maintenance

"Announce now", auto-restart schedule: off / daily / weekly.

Confirm-gated resets: clear routes & data, factory reset, full reset.

m /page/m.mu — Restart & update
  • Restart (confirm-gated, ~15s offline)
  • nRF52: Bluetooth DFU or USB-bootloader window — ESP32 (with a spare app slot): 20-min WiFi update AP

Needs battery ≥30% or charging; one-time 2-minute confirm token.

u /page/u.mu — About

Firmware tag, board name, transport/management/NomadNet/probe destination hashes.

Telemetry

Compiled in only when the board defines HAS_ENV_SENSORS — currently the Seeed Solar Node P1.

t /page/t.mu — Telemetry

Auto-detected M5 Grove ENV sensor — ENV I (DHT12+BMP280), ENV II (SHT30+BMP280) or ENV III (SHT30+QMP6988), whichever is actually plugged in.

  • Temperature, and humidity if a humidity sensor was found
  • Pressure + calculated altitude if a pressure sensor was found
  • Which exact chips were detected (e.g. "SHT30 + QMP6988")
  • MCU die temperature, read directly off the nRF52840
  • Says plainly if nothing is attached, or the read failed
z /page/z.mu — History

Compiled in with SM_HISTORY (Solar Node P1). A sample every 10 minutes, averaged into one record an hour; 7 days are kept on the QSPI flash and survive restarts. Linked from the Admin hub. The first sample is taken 1 minute after start; until the first hour is stored the page shows the hour in progress (samples so far and their averages). Records are only written per full hour, so a node stuck restarting cannot push the stored week out.

  • 24 h battery sparkline, oldest to newest; an amber | marks a restart (the time the node was off is unknown, so the bars just continue)
  • Battery now, the 24 h min–max, and the biggest drop while not charging (e.g. -14%/11h overnight)
  • Battery min–max for each of the last 7 days, newest first
  • Sensor temperature 24 h and 7 d min/max, MCU temperature, humidity range and the pressure trend
  • Neighbours and routes now, the 24 h neighbour peak
  • Lines that would not fit in one LoRa packet are left out, battery lines first to stay

LXMF alerts

Compiled in with SM_LXMF (Solar Node P1). The node gets its own lxmf.delivery address on the same identity as the NomadNet node, announced with the node name on the same interval. Its address is on the About page.

  • Alerts to every admin: “back up” 2 minutes after a restart (reset reason, restart count, hard fault or uncaught exception if there was one, battery), and “battery low” once the battery drops below the Power page threshold + 10 % while not charging (re-armed after it recovers by another 10 %)
  • Commands from admins: send status for battery, uptime, neighbours, routes and temperature; anything else gets a short help reply. Messages from anyone else are ignored, and so are messages whose signature does not check out
  • Keys: the node needs an admin's public key to write to them. It saves it when the admin opens any page while identified (the Admins page then shows key next to them); otherwise it uses the admin's own LXMF announce if it has heard one
  • Delivery: one encrypted packet straight to the admin, after a path request if needed; retried for 10 minutes, then dropped. No propagation node, so an admin who is offline misses it. No stamps: a client that demands stamps from unknown senders will drop the alerts
  • Message time: the node has no clock, so it takes the time from page requests and incoming messages, and saves it hourly. After a restart, messages carry the last saved time until it hears a new one

JSON API

Same destination as the pages above, plain JSON replies — for scripts and dashboards rather than browsing. Toggled by the Telemetry API switch on the Home page settings.

Generated from ScotMesh.h in microReticulum_Firmware. Admin pages require being on the Admins list (/page/k.mu) or registering with a password (/page/l.mu) — everyone else sees "Admins only." Every reply is built to fit one LoRa packet, so a few pages trim their own content rather than risk silently failing to deliver.
